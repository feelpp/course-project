= Practical: a small scientific application with Apptainer

== Objectives and setup

Run a CSV analysis, identify its inputs and outputs, and package its command. Use a Linux machine with Apptainer already available (xref:apptainer/apptainer-install.adoc[access instructions]). On shared infrastructure, use the execution/build locations authorized by the teaching team. This exercise is small and requires no Python packages beyond the standard library.

== Pull, inspect and execute

[source,bash]
----
mkdir -p apptainer-lab/input apptainer-lab/output
cd apptainer-lab
apptainer --version
apptainer pull python.sif docker://python:3.12-slim
apptainer inspect python.sif
apptainer exec --cleanenv python.sif python --version
apptainer run --cleanenv python.sif -c 'print("Hello from the image")'
apptainer shell --cleanenv python.sif
----

Inside the shell run `pwd`, `id` and `python --version`, then `exit` to return to the host. `exec` selects a command; `run` uses the image's runscript (here derived from the Python image's default command); `shell` opens an interactive shell. `inspect` displays metadata, not a complete dependency audit.

The tag `3.12-slim` is convenient for this first pull but can change. Retain this exact SIF and record its checksum. For a rebuildable release also record the upstream OCI digest and pin the base in the definition.

== Compute a result with explicit filesystem paths

Create `input/measurements.csv`:

[source,csv]
----
time,temperature
0,18
1,20
2,22
----

Create `analyze.py`:

[source,python]
----
include::example$apptainer-lab/analyze.py[]
----

Run from the `apptainer-lab` directory on the host:

[source,bash]
----
apptainer exec --cleanenv \
  --bind "$PWD:/work:ro,$PWD/output:/results:rw" \
  --env RESULT_LABEL=baseline \
  python.sif python /work/analyze.py \
  /work/input/measurements.csv /results/summary.json
cat output/summary.json
sha256sum python.sif input/measurements.csv analyze.py > provenance.sha256
----

Expected result: count `3`, mean temperature `20.0`, label `baseline`. `/work` exposes code/input read-only; `/results` is a separate writable destination. The output survives the process because it lives on the host. The ordinary read-only image is not changed. The absolute paths avoid depending on an implicit current directory inside the container.

== Build a named application

Create `analysis.def` next to `analyze.py`:

[source,text]
----
include::example$apptainer-lab/analysis.def[]
----

On a host where definition-file builds are permitted:

[source,bash]
----
apptainer build analysis.sif analysis.def
apptainer inspect --runscript analysis.sif
apptainer run --cleanenv \
  --bind "$PWD/input:/input:ro,$PWD/output:/results:rw" \
  --env RESULT_LABEL=packaged \
  analysis.sif /input/measurements.csv /results/packaged.json
cat output/packaged.json
sha256sum analysis.sif > analysis.sif.sha256
----

Building from a definition can require configured user namespaces/fakeroot or an administrator-supported build method. If it is unavailable, use the instructor-provided `analysis.sif` and verify its supplied checksum with `sha256sum -c analysis.sif.sha256`. Running a supplied image and building one are separate capabilities. Do not change cluster security settings to make a build work.

== Hands-on exercise

. Change one measurement in a copy of the input and predict the new mean before executing.
. Repeat the original run into another output file. Compare the two baseline results with `diff`.
. Try an empty input or a missing `temperature` column; explain the failure rather than accepting a result.
. Commit the source, definition, small input and execution instructions. Ignore SIFs and generated output; record where the exact SIF is stored and its checksum.

== Common mistakes and self-check

* A host path and a container path are different names. Locate the file at both ends of each bind.
* Writing under `/input` should fail because it is read-only. Choose `/results` for generated files.
* `--cleanenv` does not pin an image or dataset. Which files and settings still identify this run?
* A changed label alone changes the JSON, not the numeric result. Compare scientific values with the appropriate tolerance when moving to numerical libraries.
* A container does not grant access to files you cannot read on the host. Never mount secrets merely to make a command work.
