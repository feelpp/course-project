= Self-assessment

Use demonstrations rather than counting familiar tool names. Record a command, small result or repository link for each check. A gap points to a specific lesson; it does not change your enrolment from M2 to M1.

[cols="2,3",options="header"]
|===
|Demonstrate |Review if needed
|Find a data file; filter its rows using a pipe; explain a relative path and `PATH`.
|xref:linux:shell.adoc[Shell], xref:linux:files.adoc[files], xref:linux:text-processing.adoc[text processing]
|Explain the public/private key distinction and connect to a remote host.
|xref:linux:ssh/ssh-setup.adoc[SSH]
|Stage a selected change, commit it, create a branch and explain a PR.
|xref:git-github:git-starter.adoc[Git], xref:git-github:github-review-projects-lab.adoc[GitHub lab]
|Run Python in an isolated environment; compile and explain a {cpp} program using a function and a standard container.
|xref:m1:environments.adoc[Python and {cpp} environments]
|Open a remote workspace and explain where its terminal runs.
|xref:linux:ssh/remote-ssh-vscode.adoc[Remote SSH]
|Submit a short batch job; find its output; explain login versus compute nodes.
|xref:m1:gaya.adoc[Gaya]
|Run a test and describe how someone else would reproduce a result.
|xref:m1:workflow.adoc[Project workflow]
|===

Before M1, programming familiarity is expected, including {cpp}. Learn the operational tools throughout M1. At M2 entry, all the checks above are assumed; use xref:m2:transition.adoc[the M1-to-M2 bridge] for targeted revision.
