= SSH setup for scientific work

== Why this matters and objectives

Connect from your laptop to a scientific Linux host without exposing credentials. Understand key pairs, verify the server and reuse a named configuration in the terminal and VS Code.

== Keys and the agent

Check `ssh -V`. You need a client on the laptop; the institution administers the server. Inspect `~/.ssh` before creating a key so you do not overwrite an existing one.

[source,bash]
----
ssh-keygen -t ed25519 -C "your_email@example.com"
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
----

Choose a passphrase. The private key (`id_ed25519`) stays private; the `.pub` file may be registered with the server. The agent holds an unlocked key for authentication. Reuse an existing agent if your desktop already provides one.

Using your institution-issued login and following its registration policy:

[source,bash]
----
ssh-copy-id -i ~/.ssh/id_ed25519.pub your_login@gaya.math.unistra.fr
----

This requires an already permitted way to authenticate. If password access or `ssh-copy-id` is unavailable, register the public key through the administrator's procedure. GitHub public-key registration is separate.

== Verify the host and configure an alias

Before accepting a first-connection fingerprint, compare it with the administrator's trusted published value. `known_hosts` records server identities. An unexpected changed-host-key warning needs verification; do not bypass it by disabling checks or blindly deleting the record.

Save this in `~/.ssh/config`, replacing the login:

[source,text]
----
Host gaya
    HostName gaya.math.unistra.fr
    User your_login
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ForwardAgent no
----

Then run `ssh gaya`. Protect private keys with owner-only access (`chmod 600 ~/.ssh/id_ed25519`); the SSH directory should be accessible only to you (`chmod 700 ~/.ssh`). Never copy private keys to GitHub, a repository, an AI service or the cluster to solve a login problem.

== Exercise, mistakes and self-check

Connect, run `hostname` and `pwd`, then `exit`. Explain which commands ran on the laptop versus the remote machine. A failed login can mean a wrong username, missing public-key registration, wrong identity, inaccessible network or server policy; read `ssh -v gaya` output and redact sensitive details before sharing it.

Ed25519 is the default example. Legacy systems may require an administrator-approved alternative such as RSA; algorithm details are reference material, not the core login workflow. See https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent[the key-generation reference].
